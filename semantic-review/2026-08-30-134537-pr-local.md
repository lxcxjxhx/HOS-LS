# ECATSL task 2.3 crash-recovery correction re-review (v2)

The correction closes the in-flight rollback and lock-release holes, separates replay attempts from committed logical outcomes for newly journaled operations, rechecks migrations under the writer lock, and removes no-key journal amplification. Policy replay now binds the candidate, decision, and normalized failures, while compare-and-append replay reports the committed successor. Upgrade paths from schema v2-v4 do not receive equivalent transaction linkage or attempt ownership, and Windows process-query failures are still treated as proof of owner death. **Watch for:** **High · confirmed** migrated idempotency results remain outside committed logical-state detection; **Medium · confirmed** unfinished v4 attempts cannot be recovered after v5; **Medium · confirmed** duplicate policy failure keys commit but reject replay; **Medium · confirmed** attempt terminals can be attached to another transaction; **Medium · confirmed** Windows liveness-query failures can interrupt a live owner.

## High-level view

The prior `BaseException` rollback/lock-release finding is resolved for repository and future-migration writers. Committed-outcome isolation is resolved for operations created under schema v5, but **High · confirmed:** v2/v3 idempotency rows upgraded through v4 retain a null transaction link, so their durable result does not force the logical journal state to `COMMITTED`.

Owner-death recovery now has per-attempt PID and process-token metadata, and concurrent constructors no longer interrupt a registered live attempt. **Medium · confirmed:** v5 does not convert unfinished v4 `STARTED` rows into owned attempts, and **Medium · confirmed:** Windows API failures are interpreted as a dead process rather than an unknown liveness result.

The concurrent migration applicability recheck is resolved under `BEGIN IMMEDIATE`, including the two-installer regression. The prior policy substitution gap is resolved for candidate lineage, policy kind/version/outcome, inputs, audit data, ordering, and relationships; **Medium · confirmed:** an allowed initial request containing duplicate `AuditFailureRecord.missing_element` values is normalized and committed, then rejected by replay.

Compare-and-append replay now returns the successor as `actual_head_id`, and no-key writes no longer create journal rows. Crash/concurrency coverage now includes caught `BaseException`, abrupt subprocess exit, live-constructor recovery, migration rollback, and concurrent migration installation, but not the confirmed legacy-upgrade and Windows failures. The task-2.2 static proof boundary remains preserved: supported adapter identity, authorized path binding, sanitizer status, and path-bound lineage are still required before confirmation.

<summary>Issues (5)</summary>

1. **High · confirmed — Legacy committed results are not transaction-linked** — Schema v4 adds a nullable `transaction_id` to existing idempotency rows without backfilling it, so v5 reports a successful legacy replay as `REPLAYED` and can expose a later replay failure as the logical state. Backfill deterministic transaction/link rows during upgrade or make durable-result detection recognize legacy idempotency ownership.
2. **Medium · confirmed — Unfinished v4 attempts are unrecoverable after v5** — v5 adds nullable event attempt IDs and a new attempt table but does not convert existing terminal-less `STARTED` rows; both recovery paths inner-join the new table and skip them forever. Mark legacy starts interrupted during migration or create explicit legacy attempt records.
3. **Medium · confirmed — Duplicate policy failures violate replay idempotency** — the first call silently keeps the last failure for each `missing_element`, while replay rejects the unchanged request as duplicate. Reject duplicates before the first write or apply the same deterministic normalization during replay validation.
4. **Medium · confirmed — Attempt terminals can cross transaction boundaries** — `ecatsl_transaction_event.attempt_id` has no foreign key and the legal-transition trigger checks only the attempt ID, allowing a terminal event under transaction B to close an attempt owned by transaction A. Enforce attempt existence and matching `transaction_id` in the trigger or rebuild the table with the required relational constraint.
5. **Medium · confirmed — Windows query failure is treated as owner death** — failed `OpenProcess` or `GetExitCodeProcess` calls return `False`, and recovery interprets that as proof the owner died. Use alive/dead/unknown liveness and recover only on confirmed death, with a verifiable process-incarnation token.

## Schema v5 leaves legacy durable results outside logical commit detection

**High · confirmed.** Migration v4 adds nullable `ecatsl_idempotency_key.transaction_id` without a data migration (`src/ecatsl/schema.py:590-592`); migration v5 only adds attempt structures (`schema.py:595-638`). `transaction_state` recognizes a durable result only when an idempotency row links to the current transaction ID, then maps that condition to logical `COMMITTED` (`src/ecatsl/artifact_repository.py:608-627`).

A populated v3 fixture upgraded through v5 retained `transaction_id = NULL`. Replay returned the correct artifact, but `transaction_state` reported both logical and latest-attempt state as `REPLAYED`; a failed replay would likewise expose attempt-local `FAILED` despite the durable pre-upgrade result.

## Schema v5 strands unfinished v4 journal entries

**Medium · confirmed.** V5 adds nullable `attempt_id` to existing events and creates `ecatsl_transaction_attempt` without backfilling either (`src/ecatsl/schema.py:595-605`). Repository recovery starts from `ecatsl_transaction_attempt` and inner-joins its `STARTED` event (`src/ecatsl/artifact_repository.py:571-580`); migration recovery does the same (`src/ecatsl/schema.py:725-732`).

A v4 fixture with one stale `STARTED` transaction upgraded with zero attempt rows, and repository construction with a zero-second stale threshold left it at `STARTED`. Operations that are never retried remain permanently misclassified.

## Policy failure normalization differs between commit and replay

**Medium · confirmed.** Initial policy persistence keys supplied failures by `missing_element`, retaining the last duplicate and emitting one normalized failure per unique element (`src/ecatsl/artifact_repository.py:1223-1245`). Replay rebuilds that dictionary but rejects it when its size differs from the original sequence (`artifact_repository.py:1821-1826`).

An unchanged request with two valid failures for `catalog_revision` committed one normalized failure on the first call; immediate replay raised `ImmutableArtifactError: policy request contains duplicate missing elements`.

## Attempt transition constraints do not bind attempts to transactions

**Medium · confirmed.** V5 adds `attempt_id` without a reference to `ecatsl_transaction_attempt` (`src/ecatsl/schema.py:595-605`). The terminal index and transition trigger enforce one start and one terminal by attempt ID, but every trigger lookup ignores `NEW.transaction_id` (`schema.py:607-635`).

A fresh v5 database accepted `STARTED(transaction A, attempt A)` followed by `COMMITTED(transaction B, attempt A)`. Recovery then treats attempt A as terminal and cannot recover transaction A; append-only triggers make the malformed association permanent.

## Windows liveness errors can falsely interrupt a live operation

**Medium · confirmed.** `_pid_is_alive` returns `False` when Windows `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` returns no handle or `GetExitCodeProcess` fails (`src/ecatsl/schema.py:54-63`). Those failures mean liveness could not be queried, not that the process exited. The process token is checked only for the current PID; every other PID delegates to this boolean (`schema.py:73-81`).

Recovery appends the attempt's only terminal event on that `False`. If the live writer resumes, the single-terminal constraint rejects its `COMMITTED` event and rolls back the artifact transaction. The spawned-process test covers normal exit detection, not inaccessible handles or failed exit-code queries.
