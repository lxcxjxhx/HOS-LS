Task 1.1 now revalidates artifact copy/update operations so changed canonical content receives a new identity, and the focused model/scope suite passes. The shipped scope gate and `PathEvidence` shape retain the required early-out and static-proof boundaries. The remaining blocker is the reuse baseline: it does not faithfully record all concrete reuse points approved by the design, so later batches cannot rely on it as the required implementation-before-invention audit. **Watch for: confirmed — the inventory omits existing catalog batch import, discovery, PureAI/RAG, and persistence reuse points and records unrelated components as the only evaluated alternatives for several gaps.**

**Verdict**: NEEDS_CHANGES

## High-level view

The versioned reuse artifact enforces first-match selection only among the candidates it contains, but that candidate set is not the concrete inventory promised by the design. The result is self-consistent rather than complete: omitted components can never be selected or documented as evaluated.

## Reuse selection cannot account for omitted existing capabilities

**Confirmed blocker.** `task_1_1_reuse_inventory()` divides entries between `gap_entries` and `selected_entries`, but several gap decisions evaluate only an unrelated component: artifact identity and candidate contracts inspect `VerificationAdapter`, discovery inspects only `InputTracer`, and tooling/LLM telemetry inspects only `src.ai.client` (`src/ecatsl/models.py:391-437`). The approved design explicitly identifies `BatchImportManager` for catalog ingestion, repository parsers/config readers/call-graph/static outputs for discovery, existing PureAI plus AI-client telemetry for fallback, and SQLite/Pydantic dependencies for persistence (`design.md:101-110`); Requirement 5 also names RAG as an existing capability that must be exhausted. None of those omitted reuse points can participate in the first-match validator.

This blocks Requirement 7.1, which requires the inventory before implementation, and Requirement 7.3, which requires the evaluated reuse entries and unmet interface for each new abstraction. The completeness test derives its expected capability mapping from the same `TASK_1_1_REUSE_ABSTRACTIONS` constant and asserts only five selected components, so it cannot detect divergence from the design inventory. Populate the ordered candidates from the inspected repository surfaces and independently assert the design-mandated concrete reuse set and each selected-or-gap decision.
