# Append-only ECATSL schema installation on the catalog database

The change adds a versioned SQLite migration for ECATSL persistence and installs it from `CatalogImporter`. Several constraints do not match the artifact and recovery contracts: duplicate pipeline stages cannot be retained, lineage can split across two predecessor columns, and artifact IDs need not match their content hashes. Migration history is mutable and incomplete applied-version histories can be reordered rather than rejected. The focused suites pass, but they do not exercise a genuinely pre-ECATSL populated database or checksum/retry behavior.

**Watch for:** **[High, confirmed]** `stage_identity` uniqueness prevents the required duplicate-stage recovery path; **[High, confirmed]** candidate/scope/reuse lineage can have multiple roots or disagree with the generic artifact predecessor; **[Medium, confirmed]** persisted identities can violate the content-addressed model; **[Medium, confirmed]** schema-version history can be edited and non-contiguous histories are accepted; **[Medium, confirmed]** migration tests populate only after migration and omit checksum/retry coverage.

## High-level view

**[High, confirmed]** The pipeline-stage table models `duplicate_of_artifact_id` but makes `stage_identity` globally unique. Requirement 7.5 therefore cannot persist both matching stages when consolidation fails.

**[High, confirmed]** Versioned entities store predecessor state in both `ecatsl_artifact` and specialized tables without requiring equality. SQLite also permits multiple `NULL` values through the current uniqueness constraints, allowing multiple roots for one candidate, scope, or reuse inventory.

**[Medium, confirmed]** The artifact model defines `artifact_id` as `sha256:<content_hash>`, while the schema validates only the hash’s shape. Invalid persisted IDs cannot round-trip through the model layer.

**[Medium, confirmed]** Declared migrations must be contiguous, but applied rows are checked only for a too-new maximum and per-version checksum equality. The version table is mutable, and a ledger containing version 2 without version 1 installs version 1 after version 2 instead of failing closed.

**[Medium, confirmed]** The compatibility test constructs `CatalogImporter` before inserting catalog data, so it never tests a populated legacy catalog. Checksum mismatch, post-failure retry, history gaps, and recovery-specific graph constraints are uncovered.

<summary>Issues (5)</summary>

1. **[High, confirmed] Duplicate-stage recovery blocked** — `UNIQUE(stage_identity)` prevents retaining both matching stages after consolidation persistence fails. Model canonical identities separately from retained execution instances, or condition uniqueness on successful consolidation.
2. **[High, confirmed] Split and multi-root lineage accepted** — specialized predecessors can differ from `ecatsl_artifact.predecessor_id`, and multiple `NULL` roots are allowed. Use one predecessor or enforce equality and one root per logical entity.
3. **[Medium, confirmed] Artifact identity invariant missing** — the schema accepts an `artifact_id` unrelated to `content_hash`. Add `CHECK(artifact_id = 'sha256:' || content_hash)` and use valid IDs in tests.
4. **[Medium, confirmed] Migration ledger is mutable and order-insensitive** — version rows can be edited/deleted and gapped histories are backfilled out of order. Make the ledger append-only and require applied versions to be an exact prefix.
5. **[Medium, confirmed] Legacy migration and retry coverage missing** — current tests migrate before populating and omit checksum mismatch, corrected retry, and the invalid graph cases above. Create a pre-change populated database first and add targeted recovery tests.

<details><summary>Details</summary>

## Duplicate pipeline stages cannot survive consolidation failure

**Severity: High. Confidence: confirmed.** `ecatsl_pipeline_stage.stage_identity` is `UNIQUE` at `src/ecatsl/schema.py:211`, while the table exposes `duplicate_of_artifact_id` at lines 215–217. Requirement 7.5 requires matching stages to remain persisted and executable when consolidation fails; two matching stages necessarily share the identity. An in-memory reproduction inserted the first stage, then found that SQLite retained only that row when a second matching row referenced it as the duplicate. Remove unconditional uniqueness or separate canonical identities from execution instances so the failure path can store both.

## Candidate, scope, and reuse histories can split into incompatible chains

**Severity: High. Confidence: confirmed.** The generic predecessor is constrained at `src/ecatsl/schema.py:75–77`, while candidate lineage stores another at lines 97–101; the nullable pattern repeats for scopes at lines 181–186 and reuse inventories at lines 198–203. No constraint requires the two predecessors to match, and SQLite uniqueness permits multiple `NULL` roots. An in-memory insertion accepted two roots for one `candidate_id`, then accepted a third row whose generic predecessor was the first root while its candidate predecessor was the second. Use one authoritative predecessor, or add equality enforcement and partial unique indexes allowing exactly one root per entity.

## Persisted artifact IDs are not tied to their content hashes

**Severity: Medium. Confidence: confirmed.** The model computes `artifact_id = "sha256:" + digest` and rejects mismatches at `src/ecatsl/models.py:62–68`. The table declares an unconstrained text primary key at `src/ecatsl/schema.py:67` and checks only that `content_hash` is 64 lowercase hexadecimal characters at lines 70–71. The test helper inserts IDs such as `root` with unrelated hashes at `tests/unit/ecatsl/test_schema.py:28–43` and lines 103–104. Add the ID/hash check and update fixtures to persist model-valid identities.

## Migration history can be rewritten or applied out of order

**Severity: Medium. Confidence: confirmed.** `ecatsl_schema_version` is created at `src/ecatsl/schema.py:245–251` but absent from the append-only trigger list at lines 49–62. Installation validates declared migrations at lines 270–272, yet stored history is checked only via `max(applied)` and independent per-version lookups at lines 280–295. A database containing a valid version-2 row but no version-1 row is accepted and version 1 is committed afterward. Protect version rows from update/delete and reject any applied-version set other than an exact prefix before executing DDL.

## Current tests do not exercise the upgrade and retry boundary

**Severity: Medium. Confidence: confirmed.** The populated-catalog test creates `CatalogImporter` at `tests/unit/ecatsl/test_schema.py:47–49`, invoking the installer at `src/nvd/catalog_import.py:104–105`, then inserts data and reruns `_create_schema()` at test lines 50–54. It tests idempotence on an already-migrated database, not migration of a populated pre-ECATSL database. The rollback test does not retry a corrected migration, and no test covers checksum mismatch, newer/gapped ledgers, duplicate-stage recovery, multiple-root rejection, cross-table predecessor equality, or artifact ID/hash equality. Build the legacy schema and rows before opening `CatalogImporter`, then add these focused cases.
