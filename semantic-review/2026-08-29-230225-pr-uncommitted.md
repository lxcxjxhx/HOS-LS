# Immutable ECATSL foundation models and scope gate

Task 1.1 introduces frozen Pydantic contracts for ECATSL artifacts, discovery, static-path evidence, scope decisions, reuse selection, telemetry, datasets, and reports, plus the shipped Python/CWE scope and predecessor-linked revisions. The batch is not safe to submit as a small PR because ordinary Pydantic copying can detach artifact content from its canonical identity, and the required reuse record has not been instantiated.

**Watch for:** **confirmed** stale content hashes after `model_copy(update=...)`; **confirmed** absence of a concrete versioned `ReuseInventory` for the new ECATSL abstractions.

**Safe to submit:** No. Both high-severity findings should be fixed before submission.

## High-level view

The artifact base computes identity during validation and freezes normal attribute assignment, but Pydantic’s standard copy API bypasses that validation. A copied artifact can carry changed proof or provenance content under the original `artifact_id` and `content_hash`, breaking the foundational content-addressing guarantee.

Reuse selection validates that an entry chooses the first matching component or documents a gap. The implementation does not create the versioned inventory required before introducing these ECATSL-specific abstractions, leaving no auditable baseline of the existing HOS-LS components evaluated.

## Frozen artifacts can be copied with stale canonical identity

**High — confirmed.** `Artifact.assign_content_identity` computes the digest only when validation runs, while inherited `BaseModel.model_copy(update=...)` does not validate updates. Calling `observation.model_copy(update={"producer": "tampered"})` changes the serialized producer while retaining the original `artifact_id` and `content_hash`. The same path can alter evidence, provenance, sanitizer status, or identity fields, allowing persistence introduced in task 1.2 to accept different payloads under one content-addressed key.

Override artifact copying so updates reconstruct through full validation and identity recomputation, or guard the unchecked copy path and expose a validated successor factory. Extend the immutability tests to update content through `model_copy`, assert a new matching hash/ID, reject stale supplied identities, and cover nested provenance changes.

## New abstractions have no recorded reuse baseline

**High — confirmed.** `ReuseInventoryEntry.select_first_match_or_gap` enforces ordering inside a single entry, but the change only defines the reuse types and a synthetic test fixture. It does not create a versioned inventory artifact covering the introduced artifact, scope, discovery, path, telemetry, dataset, and report abstractions, despite task 1.1 requiring an entry before each new ECATSL abstraction. The design document’s prose table is not a content-addressed `ReuseInventory` record usable by subsequent repository and orchestration tasks.

Add a shipped, validated inventory artifact or deterministic inventory seed that records each task-1.1 capability, ordered evaluated HOS-LS components, and either the first match or the gap plus distinct responsibility. Add a completeness test that fails when an ECATSL capability lacks an inventory entry, rather than testing only selection inside a hand-built entry.
