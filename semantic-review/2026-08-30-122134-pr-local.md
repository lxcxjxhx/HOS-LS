## Exact result identities replace type-only replay checks

The prior implementation proved only that replayed artifacts had expected model types. `_lookup_idempotency` now compares the stored ordered ID tuple with an operation-specific expected tuple before loading results, making identity, cardinality, and ordering part of the replay contract.

The new regression replaces a committed result with a different valid `AcceptancePolicy` ID and receives `ImmutableArtifactError`. The same tuple comparison rejects trailing IDs and reordered compound results.

## Classification replay preserves dynamic missing-lineage semantics

A fixed result-ID tuple would require rerunning lineage availability decisions that may change after the first commit. `_validate_classification_replay` instead allows only missing identifiers derived from the original request, requires the classification to otherwise equal that request, and regenerates the expected `AuditFailureRecord` sequence. Substituted classifications and altered failure sets or ordering are rejected.
