# Migration-safe ECATSL persistence corrections (v2)

The correction closes all five findings from the prior task 2.1 review without changing the catalog API. Duplicate-stage recovery, versioned lineage, artifact identity, and migration-history invariants are now enforced at the SQLite boundary. Tests now cross a populated pre-ECATSL migration boundary and exercise checksum, rollback, retry, and invalid-graph behavior. No remaining or new actionable production issue was found in task 2.1.

**Watch for:** No unresolved production concern identified; all five prior findings are **confirmed resolved**.

## High-level view

Stage identity is unique only for canonical stages; a retained duplicate must reference both the matching canonical stage and its consolidation-failure audit record. This preserves normal deduplication while allowing requirement 7.5 recovery.

Candidate, scope, and reuse histories now permit one root per logical entity, keep predecessor references entity-scoped, and require specialized lineage to match generic artifact lineage. Artifact IDs must also equal `sha256:` plus their stored content hash.

Migration rows reject update/delete operations and must form an exact, checksum-valid prefix before pending DDL runs. The tests now create and populate the legacy catalog before opening `CatalogImporter`, then cover corrected retry and the previously missing identity, lineage, ledger, and stage-recovery cases.

**Resolution confidence: confirmed.** `idx_ecatsl_pipeline_canonical_identity` limits uniqueness to rows without `duplicate_of_artifact_id`. `ecatsl_pipeline_duplicate_requires_failure` requires a retained duplicate to share the canonical identity and reference a related `pipeline_stage_consolidation` failure; the focused test persists both rows and rejects undocumented duplicates.

## Candidate, scope, and reuse lineage cannot split

**Resolution confidence: confirmed.** Partial unique indexes enforce one root per entity, composite foreign keys keep predecessors within that entity, and null-safe insert triggers require each specialized predecessor to equal `ecatsl_artifact.predecessor_id`. Focused tests reject second roots, split parents, and second successors.

## Artifact IDs are bound to stored hashes

**Resolution confidence: confirmed.** `ecatsl_artifact` now checks `artifact_id = 'sha256:' || content_hash`; fixtures use valid IDs and a mismatched ID is rejected.

## Migration history is immutable and ordered

**Resolution confidence: confirmed.** `ecatsl_schema_version` has append-only triggers. Installation requires applied versions to be the exact `1..N` prefix and validates every name and checksum before running pending statements in the same rollback-capable transaction.
