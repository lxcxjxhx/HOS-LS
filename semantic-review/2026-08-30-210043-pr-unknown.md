The per-test setting correctly defines a 100-example Hypothesis budget instead of relying on global defaults. **Confirmed concern:** optional installation plus `importorskip` means neither local nor CI execution is guaranteed to meet that budget; this environment demonstrated the skip.

It proves direct predecessor persistence, named causes, and counterexample linkage, but does not cover a REJECTED candidate at the compiler boundary or every validation-policy outcome.

## Hypothesis is declared but the property test can disappear

`pyproject.toml` pins `hypothesis = "6.112.6"` in the Poetry development group and exposes it through the `dev` extra. `@settings(max_examples=100, deadline=None)` therefore requests 100 valid generated examples whenever the dependency is installed and collection succeeds.

**Confirmed concern:** the import is guarded by `pytest.importorskip("hypothesis")`. Running the targeted test in the current virtual environment raised `ModuleNotFoundError: No module named 'hypothesis'`; pytest reported it as skipped. A missing CI dependency can therefore produce no Property 1 execution rather than a failing job. The attempted Hypothesis statistics option was unavailable for the same reason.

## Acceptance threshold omits rejected compilation exclusion

Repository-origin evidence fulfills `independent_evidence`, and the generated confidence crosses the 0.5 threshold, exercising ACCEPTED and UNACCEPTED acceptance outcomes. The early return submits the latter to the compiler and confirms exclusion.

**Confirmed concern:** no candidate is REJECTED and no rejected candidate reaches the compiler. A regression that compiles REJECTED records passes this test. Add a rejected candidate/successor with otherwise-valid evidence, then assert `compiled is False`, `rejected is True`, and the retained exclusion validation.

## Predecessor retention is concrete; diff assertions are not

Reloading `root` after acceptance and `accepted` after validation, while asserting each direct `predecessor_id`, checks append-only lineage in both transitions. The validation successor includes the counterexample ID; persisting that successor requires the referenced artifact to already exist, so the path verifies retention as well as linkage.

**Confirmed concern:** `assert accepted.changed_data` establishes only non-emptiness, and the validation successor's diff is never checked. Assert the acceptance `policy_outcome` and `policy_version`, followed by validation kind, outcome, policy outcome, and policy version, to prevent unrelated metadata from satisfying the property.

## Validation policy coverage is restricted to one invalidation

The accepted branch retains a `NO_PATH` result and counterexample, maps it to UNACCEPTED, preserves confidence, and confirms later compilation exclusion.

**Likely concern:** the suite does not exercise `REJECT` or the unmapped-validation fail-closed result. If "validation policy state" requires all supported policy outcomes, those states can regress unnoticed. Add those cases and assert that neither path promotes a candidate to ACCEPTED.
