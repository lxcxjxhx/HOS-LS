# 研究方案 v2：AI 变更的可归因、可证伪漏洞验证（DCAV）

> 起草：2026-09-11。取代 v1 方案（见 `docs/archive/ecatsl-spec-v1-archive.md`；
> 全部旧方案材料统一索引见 `docs/archive/legacy-lines-archive.md`）。
> 依据：Jiahong 116 行评审意见（2026-09-11）。工作代号 **DCAV**
> （Differential–Counterfactual Attribution & Verification，暂定名，可再议）。

## 1. 主问题定义（收紧后）

**输入**：`R_before, task, Δ_AI, R_after`（Δ 为 AI 生成的 patch；是否 AI 生成
作为实验分组变量，不是问题定义前提）。

**输出**：三值判定 + 证据包：
1. `NEW_VULN`：Δ 新增了一条对安全关键操作的可达漏洞路径；
2. `NO_NEW_VULN`：未发现新增可达路径（含旧漏洞持续存在，须显式区分）；
3. `INCONCLUSIVE`：证据不足，附缺口说明。

证据包必须同时给出：**责任修改定位**（diff 内具体 hunk）+ **跨文件路径证据**
（source → Δ 引入的分支 → sink）+ **可复现的反事实实验**（安全补丁使攻击
消失；且干预保持相关功能）。核心可证伪要求：该漏洞机制在 `R_before` 中
不存在，在安全反事实或正确补丁中消失。

**两条机制的定位**（按导师意见，不作为论文立足点）：
- **SAL**（候选缩小）：把归因假设空间缩到少数竞争假设（候选 hunk / 候选
  路径），由实验增益决定去留；
- **DEP**（差分反事实实验）：**升级为系统的核心验证机制**——不只是评测
  协议，而是在跨文件依赖约束下自动选择少量保持功能的干预，区分竞争归因
  假设，按实验结果更新候选原因（假设淘汰式更新，具体规则在 P2 设计）。

**焦点场景**（与验证链最契合的 AI 生成代码缺陷，局部看似正确、需仓库级
上下文 + 差分证据才能判定）：
- 权限检查作用域错误（检查了主入口但新路径绕过）；
- 遗漏 sibling path（同类接口改了一处漏了兄弟处）；
- 不完整修改（主路径修复但异常路径/辅助入口仍可利用）。

**明确边界**（写进论文 limitation 口径）：修复有效 ≠ 引入原因正确（关接口、
加统一拦截都能让攻击消失）；最终产出是特定机制、输入、环境下的归因证据，
不是完整安全证明。`Pair-Correct` 不作唯一主指标——两版本都报旧漏洞不排除
新提交引入新路径。

## 2. 评测数据（两条主线）

| 线 | 数据 | 角色 | 注意事项 |
| --- | --- | --- | --- |
| AI 代码主线 | **SecureVibeBench**（105 大仓库、多文件编辑、静态+动态双 oracle） | 构造 vulnerable/secure AI patch 对的主力 | 需解决仓库快照/工作区供给（v1 教训） |
| AI 代码主线 | **A.S.E**（120 仓库级安全生成实例） | 补充 patch 对来源 | 仅覆盖四类 Web 漏洞，论文须说明范围 |
| AI 代码主线 | 自收集：多个 agent 在上述任务上的真实 patch（vulnerable/secure 配对） | 保证 Δ 真实性 | agent 多样性 ≥2 个 backbone |
| 通用副线 | **VulnGym**（408 entries / 184 advisories / 23 repos，口径以此为准；“38 框架”如引用须定义为自有技术栈统计） | 仓库级泛化证据，不支撑 AI 主张 | 先克隆到指定 commit 补齐 workdir，复用 v1 manifest 隔离语义 |

分层维度：语言 × CWE × 缺陷形态（三焦点场景 vs 其他）× patch 来源（AI/human）。
v1 运行报告结论直接继承：评估上限由数据可得性决定，工作区供给是 P1 第一任务。

## 3. 基线体系（七类，缺一不可）

| # | 基线 | 回答的问题 |
| --- | --- | --- |
| 1 | Semgrep / CodeQL（配置正确）双版本扫描 + 告警对齐 | 简单新增告警比较能解决多少 |
| 2 | 同 backbone、同预算裸 agent 三档：仅 diff / +仓库探索 / +测试执行 | 通用 agent 在同工具同预算下的上限 |
| 3 | DREA（适配双版本任务） | 仓库探索本身能否完成准确归因 |
| 4 | IRIS / SemTaint（各自支持语言的可比子集） | 已有 taint 分析的覆盖边界 |
| 5 | CodeJIT / HgtJIT（提交级预测；HgtJIT 跨项目 F1 0.63、CodeJIT 0.60） | 学习型 diff 模型的归因能力 |
| 6 | 差分测试 + Delta Debugging 式回退/缩减 | 普通测试+定位的归因证据强度 |
| 7 | 消融：SAL / DEP / SAL+DEP；定位消融 changed-files / BM25 / call graph / 随机候选 | 各机制真实增益 |

## 4. 指标体系

**主指标**（归因质量，不以 Pair-Correct 为唯一）：
- 归因正确率：责任修改定位 + 机制解释经干预验证成立的比例；
- 反事实有效性：安全反事实使攻击消失 **且** 功能保持的比例；
- 误归因率：把旧漏洞持续存在 / 无关重构 / 安全修改误判为本次引入；
- 有效实验比例 与 验证成本（干预次数、token、墙钟）。

**次指标**：定位精度（hunk 级）、解释质量（与 DagVul 一致，须与执行证据区分）、
各基线通用检测指标（仅作对齐参考，不作结论）。

## 5. 阶段计划（P0 止损优先）

### P0 止损实验（决定去留，2–3 周）
- 样本：**10–15 个真实跨文件安全修改案例**（SecureVibeBench/自收集挑选，
  三焦点场景各 ≥3），附人工核验的 ground truth（引入 hunk + 漏洞机制）。
- 三方对比：双版本静态扫描（基线 1）/ 同模型同预算可执行测试普通 agent
  （基线 2 最高档）/ DCAV 原型（SAL 缩小 + 手工辅助的 DEP 干预）。
- 逐案例记录：漏洞是否成立、归因是否正确、反事实是否有效且保功能。
- **Go/No-Go 门槛（可证伪）**：
  - Go：普通 agent 在 ≥2 个焦点场景反复失败（跨版本机制对齐或有效干预），
    且 DCAV 原型在 ≥5 案例上归因正确且反事实有效；
  - 收窄：普通 agent 稳定完成 → 课题退到 agent 失败模式研究或换场景；
  - 全灭 → 回到问题定义层重议。

### P1 数据与协议（3–4 周）
- SecureVibeBench/A.S.E 工作区供给（克隆/快照管理，复用 v1 隔离与零 claim 纪律）；
- 多 agent patch 池构建（每任务 ≥2 backbone，保留 task/diff/前后仓库四元组）；
- 双版本对齐资产：入口–对象–权限条件–敏感操作四元组对齐器（“告警数不变
  但新增可达路径”场景的机制基础）；
- 扩到 **40–60 分层样本**；预注册评测协议（指标、门槛、盲评流程）。

### P2 机制实现（4–6 周）
- SAL：候选 hunk/路径缩小（复用 v1 的 PathEvidence 候选 ledger 资产）；
- DEP：依赖约束下的干预规划器——功能保持检查、竞争假设区分度评分、
  实验结果驱动的假设更新循环；
- 修复有效性 / 引入原因正确性双通道验证拆分。

### P3 主实验（3–4 周）
- 七类基线全量对比 + 完整消融；报告第 4 节主指标体系；
- 更新 `bench/` 评测入口与 `bench/README.md`（吸收 v1 未竟任务 6.1/6.2）；
- 撰写论文主实验章节草稿。

### P4 泛化副线（2 周，可与 P3 并行）
- VulnGym 补齐 workdir 后跑通用检测对比，证明系统不绑定 AI patch 数据。

## 7. 风险与预案

| 风险 | 预案 |
| --- | --- |
| SecureVibeBench/A.S.E 获取或复现受阻 | 自收集真实 AI patch 主线顶上；基线 6（差分+Delta Debugging）权重上调 |
| 动态 oracle 环境搭建成本超预期 | P0 先用静态+人工核验 ground truth 起步，P1 再引入执行 oracle |
| 普通 agent 基线过强 | 触发 P0 收窄条款：换更难的跨版本场景或转向机制解释研究 |
| 误归因污染结果（旧漏洞/重构/安全修改误判） | 四元组对齐器强制区分新增/持续告警；评估集专设旧漏洞持续存在与纯重构类样本（吸收 TrapEval 教训） |
